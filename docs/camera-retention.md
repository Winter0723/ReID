# 景区相机自动采集与录像保留

后端加载模型和向量库后自动启动景区已启用点位的采集、检测与特征入库，不需要打开管理端。无点位的景区创建默认入口点位；桥接模式只采用在线设备。离线启动失败每 15 秒重新尝试，已经成功启动后手动停止的点位不会被自动重启；后端重启重新启用自动启动。使用单个 API 进程拥有相机，工作进程负责匹配和制作。

配置：

- `SCENIC_CAMERA_AUTO_START=1`（默认）：景区自动采集，独立于旧的 `CAMERA_AUTO_START` 纯中央摄像头开关。设置为 `0` 可关闭。
- `CAMERA_RECORDING_RETENTION_HOURS=12`（默认）：未引用景区摄像头录像的保留时长，从文件最后写入时间计算。
- 沿用 `CAMERA_RECORDING_SEGMENT_SECONDS=10`。纯预览/中央持久摄像头也定时封存，避免单文件无限增长。

每分钟分批清理已关闭的过期景区录像（每轮最多 200 条，积压时逐批处理）。清理项目别名、远端对象、本地副本、检测裁剪及向量；保留 `expired` 媒体记录用于排查。原始 `camera_monitor` 文件也清理。上传视频、模拟视频和普通 ReID 项目的媒体不受景区自动清理影响。

## 长期保存方案

使用不可变分片和持久引用关系，而不是原地覆盖文件或手工维护引用计数：

- 历史搜索结果、游览片段（包括未勾选片段）、剪辑草稿、制作快照引用的完整分片保留。
- 还在游览、匹配中或匹配失败且可重试的游览时段临时保留；没有匹配结果的游览同样保留，避免尚未成功处理就丢素材。
- 未完成/失败待重试的录像上传，以及相关后台任务受保护。
- 匹配和清理共用跨进程文件锁；失败清理可恢复，每次重试仍重新检查引用。异常或无法解析的引用默认保留。
- 本地现有硬链接使多个引用共享文件内容，删除一个路径不会损伤其他链接。绝不能将环形录像直接写回旧文件，否则所有硬链接都会看到被覆盖后的内容。

这里的 12 小时是普通录像池保留窗口，并非总磁盘容量上限。历史素材、未退园/尚未匹配成功的游览和失败任务可能持续占用空间；应处理这些业务记录后再释放引用。无法同时保证“所有历史素材永久保留”“以后任意重新剪辑”和“固定磁盘占用”。保留完整命中分片可再次调整该分片内的剪辑，但已过期的其他时段不可恢复。

后续可选扩展：

1. 命中分片加前后相邻分片的共享存档，扩大重剪范围；按合并时间区间保存，避免按游客重复拷贝。
2. 长期素材转成较低码率的完整分片，保留时间轴及素材映射；需接受画质损失并验证偏移。
3. 原始素材迁移到对象存储冷层，本地只留热缓存；节省本机空间，但增加存储费用和取回延迟。

本次实现保留原始完整分片，不自动转码，不改变既有剪辑时间偏移。自动清理是实际删除，生产部署前应按自身历史保存需求设置保留窗口。
