# 景区精剪使用与验收

景区精剪基于真实源素材生成自动草稿并支持人工微调，默认产生横版 75 秒、竖版 45 秒两种
时间线。目标时长和编辑器的预计时长均扣除叠化重叠。素材不足会缩短；两种画幅分别渲染，均包含高清成片、完整低清工作预览、
游客短试看和封面。旧单视频接口、资源和订单继续可用。

本文主要描述工作人员工作台；游客自己挑选、编辑和购买的流程见 [游客 H5](VISITOR_H5.md)。文末带日期的验收数据为历史记录，不能作为当前分支的测试总数。

## 启动与部署

沿用项目后端、RQ 和 Tauri 启动方式。精剪表由 `20260907120000_scenic` 引入，
`20260914120000_scenic` 增加领取记录；当前最新迁移还包括游客表和素材大小 BIGINT。升级已有部署前备份两库和对象存储，按 [双库运行手册](DATABASE_SPLIT_RUNBOOK.md) 分别升级两库。以下为 Scenic 命令，运行前在进程环境中显式设置正确的 `SCENIC_DATABASE_URL`，Alembic CLI 不自动选用 `.env.prod`：

```powershell
cd FastAPIBackend
.\venv\Scripts\python.exe -m alembic -c alembic.scenic.ini upgrade scenic@head
```

配置可放入已有 `.env.local`：

```dotenv
SCENIC_EDITING_ENABLED=1
SCENIC_TRACKING_ENABLED=0
# 手机能访问的后端地址；只在本机查看时可以不设置
SCENIC_PUBLIC_BASE_URL=http://192.168.1.100:2889
# 可选硬件编码；失败只回退到 libx264，保留全部剪辑效果
SCENIC_VIDEO_ENCODER=libx264
```

精剪需要完整 **FFmpeg、FFprobe、H.264/AAC、subtitles/libass 和中文字体**。
Windows 自动寻找 Microsoft YaHei；Linux 使用 Noto Sans CJK。可用 `SCENIC_FONT_FILE`
与 `SCENIC_FONT_FAMILY` 指定字体。Dockerfile 已加入 FFmpeg 和 Noto CJK。
增强渲染能力缺失会报错，不会自动退回没有声音和字幕的旧拼接器。

本地人物分析默认关闭。基础依赖现已包含实时识别所需的 `lap==0.5.13`；按主锁文件安装后无需重复安装。
设置 `SCENIC_TRACKING_ENABLED=1` 并重启 API/worker，在编辑器勾选“本地人物分析”即可启用。
`requirements-editing.txt` 和 Docker 的 `INSTALL_SCENIC_TRACKING` 参数仍保留兼容入口，但不代表关闭该功能就可以省略基础 `lap` 依赖。
复用已有 YOLO/ReID 权重，不自动下载模型；缺少依赖、多人身份不明确、画面交错或
目标太小会明确提示并保留完整画面。ByteTrack 的轨迹 ID 仅适用于同一视频。

渲染与精分析分别通过本机跨进程锁限制并发，适合单机演示。多主机 worker 需要共享
锁文件系统或在上线前替换为分布式资源调度；当前实现不承诺多主机全局并发限制。

## 工作流

1. 登记时明确确认授权、选择入口相机；若照片含多人，在匹配页指定目标人物区域。
2. 采集或上传影像，确认素材已索引；出园确认后匹配，复核游客片段。重新匹配保留
   同一目标的包含/排除和排序；已经出园的时间不会被改写。
3. 在成片页选择风格并生成草稿。素材预检会解释损坏、越界、未知时间和素材不足。
4. 分别切换横竖时间线，排序、裁切、锁定镜头，调整音乐、原声、标题、封面与构图。
   “补充拍摄时间与地点”按本机时区输入时间，提交时换算为 UTC，下一次自动编排生效；
   没有可靠时间时保留人工顺序。下方“包含”按镜头同步横竖两版；仅调整一版时使用
   右侧“用于此画幅”。任一画幅锁定的镜头需先解除锁定才能双版排除。
   配乐可试听、调整音量或选择“关闭配乐”，切换曲目或离开编辑器会停止试听。
5. 保存草稿。未保存编辑在当前应用会话切换游客和页面时保留；关闭应用或退出账号前
   请保存。打开其他草稿前需保存当前修改。修改风格后点击“重新自动编排”，原稿的人工
   修改会先保存，再生成应用新节奏的草稿。遇到修订冲突可“备份本地修改并读取最新”，
   本地备份支持恢复；恢复后检查内容，再以最新修订保存。备份也只保留在当前应用会话。
6. 提交横竖双版。提交快照不受后续编辑或重匹配影响；两版分别展示状态和重试入口。
7. 工作人员用“工作预览”检查完整低清视频，用“游客试看”检查短试看。编辑器中的画面
   为单镜头构图示意，完整音乐、字幕和人物跟随效果以生成后的工作预览为准。
   游客在未支付时只能观看短试看。
8. 两版完成后明确选择交付版本创建订单。可用原有模拟支付完成演示，再扫描领取
   二维码打开手机页。手机与后端应处于可互通网络，localhost 二维码不能跨设备访问。

## 素材、模板与数据

三种风格分别为旅行纪实、轻快打卡、温情回忆；镜头长度、节奏、转场和照片推拉均
不同。新草稿默认配乐分别为 Revelation（Indieteur）、Happy Beat（burabotti）、
Happy Moments v1.4（Centurion_of_war），均由作者在 OpenGameArt 以 CC0 发布，
允许商业成片、修改与再分发，无需署名。三首约 6 MB 的音频随应用打包，离线可用；
文件位于 `FastAPIBackend/assets/scenic_music/cc0-v1/`，不得在部署时遗漏。
`catalog.json` 记录原文件与分发文件 SHA-256、作者、来源、许可及下载日期；
详见同目录 `README.md` 和 `LICENSE_SOURCES.md`。界面提供曲目来源、授权说明和试听。

原三首程序合成演示配乐仍可选择，继续按需缓存到对象存储 `.scenic_music/1/`，
旧草稿和已提交版本使用原曲目 ID。演示音乐使用精确乐谱节拍；下载音乐可用可选
librosa 分析节拍，未安装时轻快模板使用固定节奏并提示，不影响播放和混音。
任意配乐上传和资源管理界面属于后续扩展。

素材探测、画质和跟踪缓存位于 `.scenic_analysis/`；运行锁位于 `.scenic_jobs/`。
缓存以实际文件指纹和分析版本区分。草稿、提交快照和产物关系位于 Scenic 数据库。
渲染时重新核验所有源文件及配乐指纹，文件失效会失败并保留已完成的其他画幅。

同一草稿修订重复提交返回同一任务；改变内容需保存产生新修订，再提交新成片。
失败画幅可重试，成功画幅不覆盖。删除原素材会使相关草稿不能再次渲染，已经输出
的成片仍由原订单绑定。当前景区摄像头已实现分段录像与引用保护，默认回收超过 12 小时且无业务引用的源片段；匹配片段、草稿、快照等引用会阻止回收。配置、保留边界及磁盘巡检见 [摄像头录像保留策略](camera-retention.md)。

### 2026-09-12 草稿比较与重新编排可靠性

成片编辑器新增“比较草稿”：选择一个已保存草稿作为基准，只读比较当前编辑内容，
包括尚未保存的修改。横竖版分别显示入片镜头数、扣除叠化的预计时长、镜头增删、
包含/排除、顺序、裁切、构图、原声、锁定和字幕变化；影片设置比较包括模板、配乐、
音量、标题、署名与封面。比较不会打开或覆盖另一草稿，切换游客会关闭比较面板。
素材签名地址续期及画质分析缓存变化不算剪辑变化；未保存修改仍需保存后才能提交。
此功能比较已保存草稿的当前修订，不提供每次历史保存的恢复，也不等同于两段成片的
同步播放或审美评分。已经提交的成片仍以各自冻结版本的工作预览为准。

重新自动编排会分别保留横竖版明确排除的镜头，以源素材指纹和原始时间窗识别，
避免重新匹配改变片段编号后又选回旧镜头。上一轮因目标时长未选到的候选仍可参与
下一轮选片。保留的排除镜头可在时间线重新包含；同源重叠候选采用保守排除，并
给出提示。锁定内容仍须保留，素材失效时明确失败。

渲染入口按画幅和本次处理任务加执行锁，同次任务重复投递不会重复生成或改写正在执行的任务。
等待渲染资源时发生超时或锁文件访问错误，会将对应排队画幅标为失败并开放重试，
其他已成功画幅保持不变。旧任务的迟到错误不能覆盖已经重试的新任务状态；立即重试的新任务也不会因旧尝试仍持锁而被跳过。
若锁目录本身无法访问，失败画幅和处理任务仍优先落库；父记录聚合失败写入日志，
恢复目录权限后可从画幅重试入口继续。

排除镜头的可见时间线条目仍按模板裁短，避免原始长时间窗导致草稿无法保存。
每版时间线最多 100 条，累计的其他排除意图保留在草稿中，并给出未展示数量提示。

空结果和失败重试。轮询保留筛选/页码，过期请求不会覆盖新结果，切换项目会重置筛选。
历史按当前景区项目查询，审计支持关键词、操作和日期筛选；任务接口也提供分页筛选。

计算，新版本失败不会遮住旧订单。待办可以交叉，不代表系统已替代人工确认游客身份。

领取。确认后仍可在有效期内下载。单版旧订单使用单版提示。
