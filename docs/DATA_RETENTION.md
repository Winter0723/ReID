# 个人数据留存与删除

下载链接过期不会自动删除照片。`VISITOR_RETENTION_DAYS` 默认 30 天；执行
`python scripts/cleanup_personal_data.py` 先查看待清理的登记 ID、对象数量和过期认证记录数量。
脚本覆盖游客参考照片、各版成片/封面/试看、草稿与登记关系、过期游客会话、邮箱验证码、
过期刷新令牌，以及没有会话/登记引用的过期游客账号。也覆盖工作人员创建的过期登记。

必须停止 API、worker、maintenance、visitor-coordinator 以及其他写入者后，执行：

```sh
python scripts/cleanup_personal_data.py --apply --writers-stopped
```

默认仅预览，不执行删除。本次修复没有对实际业务数据库运行清理。存在 queued/running
成片或仍有效订单的登记会保留；先恢复/处理失联任务，不能将“被跳过”误认为已经删除。
对象先删除、数据库后删除；对象存储失败时保留关系供重试，期间不能重新开放读写服务。
部署者应安排定期维护窗口执行，并监控失败/跳过数量，防止异常任务无限延长留存。

项目原始录像、检测裁剪、索引、人工上传媒体和审计记录属于项目数据，不能因删除一个游客
就删除其他游客仍使用的素材。现有摄像头留存维护在登记/草稿引用释放后清理未引用录像。
项目所有者应按业务期限删除整项目/媒体；备份、S3 旧版本、外部日志和 CDN 缓存另行配置期限。
人工删除请求需同时覆盖这些副本。清理脚本不会替你判断当地法定账务保存期限，执行前应
导出并单独保管必须保留的账务记录，避免用无限期保留整套照片代替账务留存。
