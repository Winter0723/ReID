# 多模型支持计划：项目固定模型，向量按特征空间隔离

> 状态：2026-10-26 已在 allinone 实施并通过自动化回归；真实业务素材阈值与排序仍需用户测试确认。
> 日期：2026-10-25。

2026-10-27 修正：原有 `ViT-MSMT17-60.pth` 由使用者确认为 **DSCL-ReID**，不是 CLIP-ReID 官方权重；历史内部适配器键保持兼容。新增 MGD-DPM 注册命令，支持多个独立权重、不同摄像头嵌入数量及显式推理配方。普通生产启动现在会通过构建缓存同步源码与镜像，避免模型接口仍停留在旧版本。

## 1. 推荐方案与使用规则

采用 **“本地模型目录发现 → 创建项目时选择 → 项目永久绑定模型版本 → 按绑定模型入库和检索”**，同时覆盖核心 ReID 和景区运营。

一个项目固定一个模型，可以避免项目内新旧向量混用。但需要区分两件事：

- **向量存储**：不同模型的数据同时保留，切换项目只改变访问目标，无需重建或搬运向量。
- **模型加载**：不同项目使用不同模型时，仍可能产生内存、显存和首次加载开销，需要独立的模型缓存机制。

首版规则确定为：

| 项目 | 规则 |
| --- | --- |
| 模型选择 | 仅在创建项目时选择；创建后不可修改，空项目也不例外 |
| 更换模型 | 新建项目，再上传或接入素材 |
| 模型目录 | 默认使用后端所在机器的 `model` 目录，可通过配置更改；API 和 worker 必须读取一致的模型文件 |
| 支持范围 | 首版支持现有 DSCL-ReID 和新增 MGD-DPM；其他架构需要新增适配器 |
| 目录发现 | 扫描权重及配套模型描述文件；缺少描述或不兼容的权重显示原因，禁止选择 |
| 文本能力 | 支持图像但不支持文本的模型可以使用，该项目禁用文本检索 |
| 默认模型 | 保留现有 DSCL-ReID；以后修改默认值只影响新建项目 |
| 模型文件变化 | 文件缺失、被覆盖或配置不匹配时停止相关推理，不自动换成其他模型 |

每个模型的描述文件记录名称、适配器、权重位置、预处理、特征输出、向量维度和能力。**文件名只是展示信息，不能作为向量兼容性的依据。**

新增 `embedding_space_id`，由权重哈希、适配器版本、预处理和特征输出规则计算，用于识别一套确定的特征空间。

## 2. 后端修改

### 新模型接入

已核对 [MGD-DPM 推理源码](https://github.com/Winter0723/MGD-DPM/blob/7ff0676817f9dc65eb27d800225670de2a99dfe4/test_mgddpm.py) 和 [Market2MSMT 配置](https://github.com/Winter0723/MGD-DPM/blob/7ff0676817f9dc65eb27d800225670de2a99dfe4/config/clip-udareid-market2msmt.yml)，新权重可以纳入首版，但需要独立适配器。

| 配置 | 现有 DSCL-ReID | 新增 Market2MSMT |
| --- | --- | --- |
| 加载方式 | 保持现有推理行为 | MGD-DPM，读取 `teacher` 分支 |
| 输入 | 保持现有配置 | RGB、256×128、bicubic、ImageNet 标准化、stride 12 |
| 特征输出 | 现有 512 维输出 | 两路残差 adapter 和 BN 后，拼接为 1280 维 |
| 推理处理 | 保持现有行为 | 原图与水平翻转图分别提取，平均后 L2 归一化 |
| 文本检索 | 保留 | 不支持 |
| 精度 | 保持现有配置 | 首版采用 FP32 |

MGD-DPM 复用现有 CLIP 视觉骨干，新增独立包装，保留 checkpoint 中训练得到的 adapter 参数。摄像头编码采用固定索引 `0`，复现该版本评测脚本的实际行为；业务相机 ID 不映射到训练摄像头索引。该选择也计入特征空间身份。

以上已确认结构可对应；实际数值一致性和检索效果留到实施验收。

### 向量库组织

采用：

```text
核心域 + DSCL-ReID 空间 → 一个 collection → 按 project_id 过滤
核心域 + MGD-DPM 空间  → 一个 collection → 按 project_id 过滤
景区域 + DSCL-ReID 空间 → 一个 collection → 按 project_id 过滤
景区域 + MGD-DPM 空间  → 一个 collection → 按 project_id 过滤
```

同模型的多个项目共用 collection，不同特征空间分开；本地 memory 后端采用对应的独立 JSON 文件。这样沿用当前项目过滤机制，又能容纳不同维度。Milvus 的 collection 可各自定义 schema，适合这里的空间隔离。[Milvus 官方说明](https://milvus.io/docs/v2.5.x/multi_tenancy.md)

模型实例按版本懒加载，首版默认每进程缓存两个实例，容量可配置。使用加载锁防止重复加载，只淘汰闲置实例；活动相机和任务持有固定实例。资源不足时明确报错，不切换模型。API 与 worker 的缓存独立计算资源占用。

接口约定：

- 新增 `GET /api/v1/models` 和 `GET /api/v1/scenic/models`，分别使用对应账号域鉴权，共用模型注册服务。
- 列表返回模型 ID、名称、版本摘要、维度、能力和不可用原因；前端不提交任意文件路径。
- 两套项目创建请求增加 `reid_model_id`。旧客户端省略时使用已注册默认模型，并立即保存为具体版本。
- 项目响应增加绑定模型信息；后续入库、检索、实时识别仍以 `project_id` 为入口，由后端决定使用哪个模型。

游客 H5 自动沿用项目模型，无需提供模型选择。旧 Qt/QML 客户端不纳入本次修改。

## 4. 已有项目与部署兼容

- 升级前核对旧项目实际使用的权重和提取配置。确认属于现有 DSCL-ReID 的项目，回填固定绑定，并将该空间映射到现有 collection／JSON 文件，**无需重新提取已有向量**。
- 无法确认来源的历史向量不直接认领为当前默认模型：保留数据并标记待核验，暂停相关推理和入库；确认原配置或显式重建后恢复。
- 同名权重被覆盖也视为模型发生变化；旧项目不能自动继承新文件。
- 升级时暂停相机入库，处理完或重新安排旧队列任务，再统一升级 API 和 worker，避免旧 worker 继续使用全局模型写入。
- Docker 从挂载单个 ReID 文件改为挂载模型目录，API 和各 worker 使用相同目录及描述文件。
- 同步模型检查脚本、环境配置示例、模型使用说明和 API 文档。

## 5. 实施顺序与验收

实施顺序：**MGD-DPM 适配及模型注册 → 项目绑定和迁移 → 向量路由及全部调用链 → 前端选择与能力展示 → 双模型回归。**

必须通过以下验收：

1. **模型正确性**：MGD-DPM 适配器与固定版本源码对同一输入输出一致；检查 1280 维、归一化、翻转融合及单张／批量一致性；旧模型输出不变。
2. **空间隔离**：两个模型同时入库、搜索不串用；模拟两个同维度但不同模型的场景也必须隔离；core/scenic 相同项目 ID 不串库。
3. **完整流程**：图片、视频、相机、实时识别、游客匹配和精分析均使用项目绑定；删除、清理和失败回滚只影响对应数据。
4. **规则与异常**：创建后改模型被拒绝；模型缺失、被替换、描述错误、worker 配置不一致均明确失败；MGD-DPM 文本检索在前后端同时被禁用。
5. **历史兼容**：两套数据库完成迁移，已确认来源的历史项目无需重算即可检索；默认模型变更不影响旧项目。
6. **实际效果**：两份真实权重分别完成上传到检索的冒烟验证，并用固定正负样本检查排序和现有匹配阈值表现；不同模型的相似度分数不视为可直接横向比较。

实施记录：项目绑定、双域迁移、目录注册、MGD-DPM teacher 适配、向量隔离、任务/相机/实时识别/景区调用链和工作台模型选择已落地。MGD-DPM 与指定提交原版 forward 的两图验证最大误差为 0，单张/批量最大误差约 1.9e-7。历史来源确认通过 `scripts/bind_legacy_models.py` 显式执行；未自动修改部署中的历史数据。纯净分支等待用户测试完成后再定期发布。

自动化验收记录：后端全量回归通过（真实权重冒烟默认跳过，另行开启后通过），前端 97 项单测、生产构建和 19 项 Playwright 浏览器回归通过。真实权重检查覆盖 DSCL-ReID 512 维、MGD-DPM 1280 维、双域入库检索及旧 CLIP 输出一致性。该冒烟使用合成人物图，不代表已完成真实业务正负样本排序和阈值验收；实体相机、生产 Milvus 以及部署中的历史数据仍需在用户测试环境验收。
